# 📝 개인 개발 블로그 PRD (Product Requirements Document)

> Notion을 CMS로 활용하는 개인 기술 블로그

## 1. 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| **프로젝트명** | 개인 개발 블로그 |
| **목적** | Notion을 CMS로 활용한 개인 기술 블로그 구축 |
| **CMS 선택 이유** | Notion에서 글을 작성하면 별도 작업 없이 블로그에 자동 반영 |
| **대상 사용자** | 기술 글을 읽는 개발자 (방문자), 블로그 운영자 (본인) |

### 1.1 배경 및 문제 정의

- 별도 관리자 페이지나 마크다운 파일 커밋 없이, 익숙한 Notion 에디터로 글을 작성하고 싶다.
- 글 작성/발행 워크플로를 단순화하여 콘텐츠 작성에만 집중한다.

### 1.2 목표

- Notion 데이터베이스에서 `발행됨` 상태로 변경하면 블로그에 자동 노출
- 빠른 로딩과 좋은 가독성의 기술 블로그 UI 제공
- 모바일/태블릿/데스크톱 전 환경 대응

### 1.3 비목표 (Non-Goals)

- 댓글, 회원가입/로그인 기능
- 다국어 지원
- 자체 관리자(Admin) 페이지

## 3. Notion 데이터베이스 구조

| 속성명 | 설명 | Notion 타입 | 비고 |
| --- | --- | --- | --- |
| `Title` | 제목 | `title` | 필수 |
| `Category` | 카테고리 | `select` | 카테고리 필터링에 사용 |
| `Tags` | 태그 | `multi_select` | 복수 선택 |
| `Published` | 발행일 | `date` | 목록 정렬 기준 (내림차순) |
| `Status` | 상태 | `select` | `초안` / `발행됨` |
| `Content` | 본문 | page content | 페이지 본문 블록 |

### 3.1 데이터 조회 규칙

- `Status = 발행됨`인 글만 블로그에 노출한다.
- 목록은 `Published` 기준 최신순으로 정렬한다.
- Notion 연동은 Integration 토큰을 통해 서버 사이드에서만 수행한다. (클라이언트 노출 금지)

### 3.2 타입 정의 (초안)

```ts
interface Post {
  id: string;
  title: string;
  category: string | null;
  tags: string[];
  publishedAt: string; // ISO 날짜
  status: "초안" | "발행됨";
}
```

## 4. 주요 기능

### 4.1 글 목록 조회

- Notion 데이터베이스에서 발행된 글 목록을 가져온다.
- 카드 형태로 제목, 카테고리, 태그, 발행일을 표시한다.

### 4.2 글 상세 페이지

- 개별 글의 본문(Notion 블록)을 렌더링한다.
- 지원 블록: 제목(h1~h3), 문단, 목록, 코드 블록, 인용, 이미지, 구분선 등
- 제목, 카테고리, 태그, 발행일 메타 정보를 함께 표시한다.

### 4.3 카테고리별 필터링

- 카테고리를 선택하면 해당 카테고리의 글만 표시한다.
- 카테고리 목록은 데이터베이스의 `Category` 옵션에서 가져온다.

### 4.4 검색 기능

- 제목(및 태그) 기준 키워드 검색을 제공한다.
- Notion API의 `filter`(title contains)를 활용한다.

### 4.5 반응형 디자인

- 모바일 / 태블릿 / 데스크톱 브레이크포인트 대응 (Tailwind 반응형 유틸리티)
- 모바일에서는 1열, 데스크톱에서는 다열 그리드로 목록 표시

## 8. 비기능 요구사항

| 항목 | 요구사항 |
| --- | --- |
| **성능** | 정적 생성(SSG) + ISR로 빠른 로딩, Lighthouse 성능 90+ 목표 |
| **캐싱** | ISR `revalidate`로 Notion 변경사항을 주기적으로 반영 (Notion API 호출 한도 고려) |
| **보안** | API 키는 서버에서만 사용, `.env.local`을 Git에 커밋하지 않음 |
| **접근성** | 시맨틱 HTML 및 적절한 대비, 키보드 탐색 지원 |
| **유지보수** | TypeScript 엄격 모드, ESLint/Prettier 적용 |

---

## 9. 리스크 및 고려사항

- **Notion API 호출 제한**: 평균 초당 3회 제한 → ISR/캐싱으로 호출 최소화
- **이미지 URL 만료**: Notion 업로드 이미지는 URL이 약 1시간 후 만료 → 빌드/재검증 시 갱신 또는 별도 이미지 저장 방안 필요
- **블록 렌더링 범위**: 지원하지 않는 블록 타입의 폴백 처리 필요
- **본문 조회 비용**: 목록은 속성만, 본문은 상세 페이지에서만 조회하여 호출 수 최소화

---

## 10. 성공 기준

- Notion에서 `발행됨`으로 변경한 글이 재검증 주기 내에 블로그에 반영된다.
- 홈/상세/카테고리 화면이 모바일·데스크톱에서 정상 동작한다.
- `npm run check-all` 및 `npm run build`가 모두 통과한다.
- Vercel 배포가 성공하고 공개 URL로 접근 가능하다.
